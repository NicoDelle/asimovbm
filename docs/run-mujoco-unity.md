# Run MuJoCo in Unity

This runbook prepares a Windows Unity project to import and run the AsimovBM
MuJoCo scene with the official MuJoCo Unity plug-in. WSL prepares the files;
Unity owns real-time simulation and rendering.

## Prepare the Unity Project

From this repository, run:

```bash
python tools/unity/prepare_mujoco_unity_project.py \
  --unity-project <path-to-unity-project> \
  --stage-real-g1
```

The default prepares MuJoCo `3.8.1`, stages
`g1_slam/assets/g1_kinematic.xml`, and places the Windows `mujoco.dll` under
the Unity project. It also copies the repo-managed AsimovBM Unity scripts,
scene manifest, tests, and local runtime settings.

To also stage the real MimicKit G1 model, STL meshes, USD source, and reference
motions:

```bash
python tools/unity/prepare_mujoco_unity_project.py \
  --unity-project <path-to-unity-project> \
  --stage-real-g1 \
  --mimickit-data-root /home/anthor/projects/neogenesis/MimicKit_Data
```

This copies the real model to `Assets/AsimovBM/MuJoCo/Models/g1/g1.xml` and
converts the default `g1_walk` and `g1_run` motion pickles to CSV files under
`Assets/AsimovBM/MuJoCo/Motions/g1/`.

Use a dry run first if you want to inspect the write set:

```bash
python tools/unity/prepare_mujoco_unity_project.py \
  --unity-project <path-to-unity-project> \
  --dry-run
```

If Unity cannot resolve the Git package dependency, rerun with the embedded
package fallback:

```bash
python tools/unity/prepare_mujoco_unity_project.py \
  --unity-project <path-to-unity-project> \
  --package-mode embedded
```

For this workstation, the Unity project path is:

```bash
/mnt/d/_PROJECTS/Unity/AsimovBM
```

## Run Validation Without UI

Close the Unity project if it is already open, then run:

```bash
PYTHONPATH=src:g1_slam/src python -m asimovbm.local_runner.unity_runner run \
  --unity-project <path-to-unity-project> \
  --run-id unity-smoke \
  --dry-run
```

When the dry run looks right, run without `--dry-run`:

```bash
PYTHONPATH=src:g1_slam/src python -m asimovbm.local_runner.unity_runner run \
  --unity-project <path-to-unity-project> \
  --run-id unity-smoke
```

The command starts Unity in batchmode, generates all scenes from
`Assets/AsimovBM/MuJoCo/SceneManifest.json`, runs the Unity PlayMode validation
test, ingests raw Unity traces through Python, and writes artifacts under
`artifacts/unity-validation/<run-id>/`.

The current validation scenes are:

- `g1_kinematic_smoke`: quick MuJoCo importer/simulation smoke scene.
- `g1_real_motion`: real MimicKit G1 model replaying `g1_walk.csv`.

Each scene writes a raw Unity JSON trace, a normalized trace, and a metrics file.
The final run-level `manifest.json` records movement proof for each scene.

If Unity reports that another instance already has the project open, close the
Unity Editor window for that project and rerun the command.

## Press Play Workflow

These are the only UI steps needed for a manual visual check:

1. Open the Unity project in Unity.
2. Wait for Package Manager resolution and C# compilation to finish.
3. Open the Console and enable Error Pause.
4. Use `AsimovBM > MuJoCo > Generate Validation Scenes` if the scenes have not
   already been generated by the terminal command.
5. Open `Assets/AsimovBM/GeneratedScenes/g1_real_motion.unity`.
6. Press Play.

Success means Play mode starts without Console errors, the G1 model moves from
the `g1_walk.csv` reference motion, lighting/materials are readable, and the
Console prints the raw Unity trace path. If the local WSL bridge is configured,
Press Play also invokes the Python ingest command and writes metrics/report
artifacts under `artifacts/unity-validation/<run-id>/`.

## Tell the Agent

After each UI checkpoint, tell the agent what happened:

- Package resolution and compilation: success or the first Console error.
- Scene generation: success or the generator/importer error text.
- Play mode: whether the robot moves and any Console errors.

## Troubleshooting

### Package Manager Cannot Fetch MuJoCo

Windows Unity needs Git available on the Windows PATH for Git package
dependencies. If package resolution fails with a Git error, rerun the
preparation tool with `--package-mode embedded`, then reopen Unity.

### `mujoco.dll` Is Missing

Confirm `Assets/Plugins/x86_64/mujoco.dll` exists in the Unity project. If it
does not, rerun the preparation tool without `--skip-dll`.

### Import Menu Is Missing

Manual import is no longer the primary path. Wait for Unity compilation to
finish, then use `AsimovBM > MuJoCo > Generate Validation Scenes` or the
terminal runner. If the menu is missing, fix the first Console compile error.

### Import Succeeds but Play Mode Is Static

Confirm the imported scene contains MuJoCo components and no Console errors
appear when entering Play mode. The official plug-in steps MuJoCo from Unity's
fixed update loop, so Console errors usually point to package, native DLL, or
scene binding failures.

The quick `g1_kinematic_smoke` scene is a smoke test, but it should still show
MuJoCo state changes. Use `Assets/AsimovBM/GeneratedScenes/g1_real_motion.unity`
to verify the real G1 model and replay `g1_walk.csv`.

The generated scene contains `AsimovUnityMovementVerifier`; Unity PlayMode
tests fail when a scene expected to move only animates diagnostics or remains
static.

### Scene Is Purple or Flat

Regenerate the validation scenes or use `AsimovBM > MuJoCo > Repair Materials
And Lighting`. Scene generation automatically converts imported MuJoCo
materials to a lit shader, adds soft directional lights, and creates a review
camera so the robot is not viewed flat from the front.

### Official G1 or Go2 Assets Fail

Start with the staged kinematic XML first. Official Unitree scenes require
their mesh/include directories to be staged with matching paths; do that only
after the kinematic smoke succeeds.
